Postausgang

Ohne diese Angaben verschickt Rechnungsblatt keine Bestätigungscodes und keine Rücksetz-Links — die Nachrichten landen dann nur im Protokoll. Das Passwort wird verschlüsselt abgelegt und nie wieder angezeigt.

Unterschrift (DKIM)

Ohne Unterschrift landet Post von einer eigenen Domain regelmäßig im Spam — ein Bestätigungscode im Spamordner ist so gut wie keiner. Die Domain muss zum Absender oben passen.

Zählung

    

      Plausible zählt Seitenaufrufe ohne Cookies. Ohne Adresse wird gar
      kein Skript eingebunden.

      Hier gehört die interne Adresse hin, so wie
      Rechnungsblatt sie im Docker-Netz erreicht — etwa
      http://plausible:8000. Der Browser des Besuchers spricht
      Plausible nie direkt an: Er holt sein Skript von dieser Seite, und
      Rechnungsblatt reicht die Zählung nach innen weiter.
    

    

      

        

      

        

      

        
        

    

    

      Den Schlüssel legen Sie in Plausible unter Settings → API Keys an. Er
      wird nur zum Lesen der Zahlen gebraucht: Ohne ihn zählt die Seite
      weiter, die Auswertung oben bleibt aber leer.

Zahlungen

    

      Ohne Schlüssel bietet die App keine Zahlung an — Tarife und Guthaben
      setzen Sie dann weiter von Hand, wie bisher. Die Schlüssel werden
      verschlüsselt abgelegt und nie wieder angezeigt.
    

    

      

        
        
        

          Nur dieser. Der „veröffentlichbare“ Schlüssel
          (pk_…) ist für
          Zahlungsformulare im Browser gedacht — Rechnungsblatt
          benutzt Stripe Checkout, da läuft alles auf dem Server.
        

      

      

        
        

      

        
        
        

          Hierfür braucht es kein Produkt in Stripe: Der
          Betrag reist mit der Zahlung mit. Ein Produkt mit mehreren Preisen
          anzulegen wäre vergebene Mühe.
        

      

    

    
    

      Der Webhook zeigt auf /api/bezahlen/webhook.
      Nötige Ereignisse: checkout.session.completed, invoice.paid,
      invoice.payment_failed, customer.subscription.updated, customer.subscription.deleted.
      Die Preis-ID eines Abos steht beim jeweiligen Tarif, nicht hier —
      so lassen sich mehrere Abos nebeneinander anbieten.
    

    

      „Managed Payments“ bleibt aus.
      Rechnungsblatt schaltet Stripes Merchant-of-Record-Dienst bei jeder
      Zahlung ausdrücklich ab. Er würde Umsatzsteuer berechnen und
      eigene Rechnungen an Ihre Kunden schicken — bei Abrechnung nach
      § 19 UStG ausgeschlossen. Außerdem kostet er 3,5 %
      zusätzlich. Sollte Stripe ihn im Konto aktivieren, ändert das
      hier nichts.
    

    

      Nur Abos brauchen eine Preis-ID. Ein wiederkehrender
      Betrag muss in Stripe angelegt sein, weil Stripe den Abrechnungszyklus
      führt und bei einer Preisänderung Bestandskunden auf ihrem
      alten Preis lässt. Guthabenaufladungen dagegen sind Einmalzahlungen
      — die entstehen zur Laufzeit aus der Betragsliste oben.
